# PLUTON 4.1 Phase 3: Project Persistence & Dynamic Multi-Builds Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement central project registration, hybrid resolution (explicit > CWD > global-active), unified multi-project server context pooling, concurrent background builds across separate projects, and web workspace project switching without cross-project state or event leaks.

**Architecture:** A central atomic registry (`~/.pluton/projects.json` and `~/.pluton/active-project`) tracks registered project paths and canonical SQLite project IDs. CLI commands resolve context through a 4-tier hybrid resolver. The application server maintains a multi-project context pool of `Store` and `LoadedConfig` handles, serving project-scoped REST and SSE streams. Background supervised builds execute concurrently across different projects in independent memory tick chains, while in-project builds reuse persistent workspaces without redundant confirmation dialogs.

**Tech Stack:** TypeScript, Node.js 24 (`node:fs`, `node:path`, `node:http`, `node:sqlite`), SQLite3, vanilla HTML/CSS/JS (embedded SPA).

**Spec:** `docs/superpowers/specs/2026-11-03-project-persistence-concurrent-multi-builds-design.md`

## Global Constraints

- **Single Store Authority:** Project state must be saved to and loaded from SQLite; JSON files only cache project location and global active ID.
- **Fail-Closed Resolution:** When no project is identifiable, commands must fail cleanly with guidance (`ProjectRequiredError`), never guess or touch random directories.
- **Atomic Pointer Writes:** Updates to `projects.json` and `active-project` must write to PID-tagged temp files and atomically rename (`renameSync`).
- **Non-Interference:** Switching the active project must never abort, pause, or alter background builds or their database transactions.
- **Contract Compatibility:** Asset contracts in `scripts/verify-assets.mjs` must be preserved and expanded to include project selector elements.
- **ADR-0005 Compliance:** Intra-project concurrency must use `GitWorkspaceManager` isolated checkouts; never shared worktrees.

## Review Focus

1. **Missing or Stale Project Directory:** A registered project path that has been deleted or moved must be flagged gracefully with clean removal options rather than crashing with unhandled `ENOENT`.
2. **Concurrent Build Cross-Talk:** Running concurrent builds on Project A and Project B simultaneously must not interleave task IDs, worker sessions, SSE activity events, or database writes.
3. **Session & File Explorer Bleed:** Switching projects in the Web Workspace must immediately clear and swap file listings and chat sessions so that no files or messages from the previous project are displayed.
4. **Active Project Collision in Parallel Terminals:** Terminal session 1 running `pluton project switch` must not silently divert a concurrently running in-flight build command in Terminal session 2 that already resolved its project context.
5. **Redundant Build Confirmation Suppression:** Starting a subsequent build on an existing project workspace must reuse the persistent workspace without presenting redundant modal confirmation while preserving tool approval gates.
