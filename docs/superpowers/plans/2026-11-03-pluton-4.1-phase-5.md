# PLUTON 4.1 Phase 5 Implementation Plan: File Explorer Scalability, Lazy Tree & Deep Navigation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Provide scalable, deep recursive file browsing, bounded path-based search, multi-file editor tabs with dirty protection, and strict project-isolated containment in Pluton's workspace explorer.

**Architecture:** Replace the synchronous 300-file walker with on-demand directory expansion (`GET /api/files?dir=...`) and deterministic offset/limit pagination in `src/server/routes.ts`. Add a bounded recursive search endpoint (`GET /api/files/search`). In `src/server/static-assets.ts`, implement a lazy-loading tree that preserves expanded folder state, breadcrumbs, search dropdown, and multi-file editor tabs with per-project/per-session state isolation.

**Tech Stack:** Node.js 24 (native `node:fs`, `node:path`), TypeScript, Vitest, Vanilla JavaScript/CSS (embedded SPA in `static-assets.ts`).

**Spec:** `docs/superpowers/specs/2026-11-03-file-explorer-scalability-design.md`

## Global Constraints

- Runtime: Node >= 24.0.0. No added runtime dependencies.
- Storage: SQLite remains authoritative; file operations resolve strictly inside project workspaces.
- Backward compatibility: `GET /api/files` returns `entries` alongside legacy `files: string[]`.
- Security: Containment via `safeResolvePath`, `realpathSync`, `protectedWorkspaceSegment`, and `resolveWorkspaceDir`.
- Secret protection: Reject access to `.git`, `.pluton`, `node_modules`, `.env*`, and files > 2MB.
- Event loop safety: Search is bounded by 10,000 scanned items and 100 matches, setting `truncated: true`.

## Review Focus

- Traversal attempt with encoded dots/slashes in `dir` query: expects 403 status and no filesystem access.
- Symlink inside workspace pointing to root directory: expects 403 status or omission from listing.
- Large directory (>500 items): expects deterministic sorting and pagination without missing or duplicated entries.
- Unsaved file buffer when switching projects/tabs: expects changes preserved and dirty close confirmation.
- Search with empty, rare, or giant tree: expects fast response, bounded scan, and no event loop locking.

   - Read immediate entries via `readdirSync(canonicalDir, { withFileTypes: true })`.
   - Filter ignored: `dist`, `.DS_Store`, `coverage`, `.git`, `.pluton`, `node_modules`, and `.env*`.
   - Skip broken symlinks or symlinks escaping canonical root.

   - Call `listWorkspaceDirectory`. Return `{ ok: true, dir, entries, files: entries.map(e => e.path), total, hasMore, offset, limit, rootDir }`.
3. Fix `targetProj` parameter in `PUT /api/files/content` and `DELETE /api/files/content`.

1. Implement `searchWorkspaceFiles(rootDir: string, query: string, limit = 100, maxScanned = 10000)`:
   - Breadth-first / bounded recursive traversal of workspace.
   - Ignore `.git`, `.pluton`, `node_modules`, `dist`, `coverage`, `.env*`.

   - Return `{ ok: true, query: q, matches, totalMatches: matches.length, truncated }`.

   - Save listener writes `activeTab.value` to `/api/files/content`, sets `originalContent = value`, clears `isDirty`.
