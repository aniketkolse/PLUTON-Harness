# PLUTON TUI 2.0 Refactor Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Refactor the Pluton-Harness terminal user interface into a polished, production-quality agentic coding TUI featuring a purple pirate-ship brand header and wordmark, structured scrollable transcript, live tool activity groups, rich result cards with diffs, a docked multiline input box, a live status bar, clean approval notifications, and an optional Orchestra inspector.

**Architecture:** Create a cohesive `src/ui/` module that centralizes theme tokens, pirate ship branding, reusable message/card/input/status components, and isolated demo mode. Integrate these components into the existing layout engine (`src/tui/layout.ts`), full-screen renderer (`src/tui/render.ts`), and chat controller (`src/chat/session.ts`) while maintaining 100% compatibility with the underlying Pluton engine adapters, SQLite persistence, tool bridge, and approval workflows.

**Tech Stack:** TypeScript (Node.js >= 24), Commander.js, ANSI escape sequences with truecolor/256/16-color fallbacks, Vitest.

**Spec:** Current prompt `PLUTON TUI 2.0 — MASTER IMPLEMENTATION PROMPT` and `docs/adr/0012-interactive-chat-tui.md`.

## Global Constraints
- Target Node.js >= 24.0.0 and ES Modules only.
- Zero new heavy dependencies (no external TUI frameworks). Use pure TypeScript ANSI rendering.
- Exact palette: Background `#0B0C10`, Primary accent `#8B5CF6`, Accent light `#A78BFA`, Info `#7C8CFF`, Links `#60A5FA`, Success `#34D399`, Error `#F87171`, Warning/Cost `#FBBF24`, Primary text `#E5E7EB`, Muted text `#6B7280`, Borders `#2A2F45`.
- Do not rewrite agent execution, engine adapters, permissions, approval state, SQLite store, or run supervision.
- Preserve fail-closed security for approvals and permissions.
- Provide ASCII and monochrome fallbacks when `NO_COLOR` is set or colors/Unicode are unavailable.

## Review Focus
1. Terminal resizing between wide (129x48) and narrow (<80x24) must adjust layout without crashing, overlapping borders, or losing draft input.
2. Ansi escape sequences and terminal control codes in tool output or assistant prose must be sanitized to prevent terminal injection.
3. Multiple concurrent tool calls must correlate by call ID without mixing outputs or showing duplicate progress lines.
4. Pinned approval cards must appear exactly once above the input, never duplicating across the transcript.
5. In demo mode (`--demo`), no external commands or real file edits may be executed.
