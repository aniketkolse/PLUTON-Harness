# PLUTON 6.0: Universal Provider-Agnostic AI Execution Architecture — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Transform PLUTON into a provider-independent AI execution platform where any supported provider, compatible API, or model executes independently with full coding tool support without requiring OpenCode.

**Architecture:** Decouple provider connections, models, and execution adapters into an explicit composite identity `(connectionId, providerId, modelId)`. Build a shared coding tool runtime directly into PLUTON's MCP bridge (`file.read`, `file.write`, `file.edit`, `file.search`, `command.exec`, `tests.run`), isolate health and quota scopes per connection, enable mixed-provider Ship teams in the supervisor, and support dynamic multi-connection management with manual capability declarations.

**Tech Stack:** TypeScript (Node.js 24 ESM), SQLite (`node:sqlite`), Zod, Vitest.

**Spec:** PLUTON 6.0 Specification & `docs/PLUTON_6.0_ARCHITECTURE_AUDIT.md`

## Global Constraints

- OpenCode is an optional execution integration, not a mandatory execution layer.
- Preserve exact provider model IDs; do not normalize or rename unless required by provider protocol.
- Credentials stored with mode 0600 in private home directories; never logged, exposed via API, or written to `pluton.sqlite` / `pluton.yaml`.
- Do not modify `pluton.yaml` without operator confirmation.
- Quotas, rate-limits, and failures must remain strictly isolated per connection.
- Shared PLUTON tool runtime must enforce existing permissions, leases, approvals, and checkout isolation across all providers.
- Bounded fallback must re-resolve execution routes and create sessions through the replacement adapter.

## Review Focus

1. Multi-segment model IDs (e.g. `nvidia/nvidia/nemotron-3.5-super-vl-120b-a12b`) must route to their configured connection, not parse `nvidia` as an unconfigured provider.
2. An auth failure or rate limit on one connection (e.g. `9router`) must not mark other connections (e.g. `groq`) or OpenCode as unavailable.
3. Supervisor must not override a user's explicitly selected `ship.model` unless dynamic selection is explicitly enabled or fallback triggers.
4. Coding tools (`file.write`, `command.exec`) executed by external models must respect workspace checkout boundaries and reject path traversal outside the task checkout.
5. Fallback from an OpenCode model to an external model (or vice-versa) must instantiate a fresh adapter rather than reusing the previous session's adapter.

## File Structure

```
src/
├── providers/
│   ├── types.ts                     # Expanded connection & provider schemas
│   ├── store.ts                     # Multi-connection config & credential store
│   └── validation.ts                # Endpoint & SSRF validation
├── engines/
│   ├── contract/
│   │   └── types.ts                 # Composite model identity & capabilities
│   ├── model-registry.ts            # Registry keyed by (connectionId, modelId)
│   ├── model-discovery.ts           # Multi-connection discovery
│   ├── model-selection.ts           # Provider-aware model selector
│   ├── model-health.ts              # Connection-scoped health monitor
│   ├── model-fallback.ts            # Multi-adapter fallback engine
│   ├── execution-router.ts          # Robust route resolution
│   └── openai-compatible/
│       ├── adapter.ts               # Connection-aware adapter
│       └── session.ts               # Streaming & tool calling session
├── tools/
│   ├── catalog.ts                   # Tool definitions including file.write & command.exec
│   ├── handlers.ts                  # Implementation of coding tools in MCP bridge
│   └── bridge.ts                    # Authorized tool bridge enforcing leases
├── orchestrator/
│   ├── supervisor.ts                # Mixed-provider supervisor & route-aware fallback
│   └── service.ts                   # Run supervisor setup & discovery wiring
└── server/
    ├── routes.ts                    # Connection CRUD & model routing API
    └── static-assets.ts             # SPA UI for connection management & model picker
```
